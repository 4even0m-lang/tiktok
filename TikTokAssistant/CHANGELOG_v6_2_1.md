# v6.2.1 — إصلاح إعداد Windows hosts

هذا إصدار إصلاحي مبني على v6.2، ولا يغيّر نظام TikTokLive أو صفحة Overlay أو محرر الإشعارات.

## الإصلاحات

- فحص منفصل لحالة ملف `hosts` وحل الاسم DNS وحالة خادم Overlay المحلي وحالة رابط `overlay.test`.
- السماح بإصلاح تعارض `overlay.test` بعد موافقة واضحة من المستخدم؛ لا تُمسّ أسماء الأجهزة الأخرى في `hosts`.
- طلب صلاحيات المسؤول بعملية منفصلة عند الحاجة فقط، دون تشغيل البرنامج كاملًا كمسؤول.
- نسخ احتياطي قبل أي تعديل ثم التحقق من النتيجة؛ لا يُعَد نجاح طلب UAC نجاحًا في تغيير الملف.
- رسالة خطأ واضحة عند فشل الأذونات أو إلغاء UAC، وخطوات تصحيح يدوية.
- إعادة إظهار الإعداد في أول تشغيل عند وجود تعارض؛ وزر فحص متاح في الإعدادات دائمًا.

## فحص المشكلة على Windows

افتح PowerShell داخل مجلد `TikTokAssistant` ثم شغّل:

```powershell
python hosts_setup.py --diagnose
```

القيم المهمة:

- `mapping`: `ready` = السطر الصحيح في الملف؛ `missing` = غير موجود؛ `conflict` = عنوان متعارض؛ `unavailable` = تعذر قراءة الملف أو ترميز غير مدعوم.
- `resolved_ip`: يجب أن يكون `127.0.0.1`.
- `server_local`: `ok` عند تشغيل الخادم المحلي، أو `unavailable` إذا كان الخادم متوقفًا.
- `server_alias`: `ok` إذا كان `overlay.test:8765` قابلًا للوصول.

شغّل خادم Overlay من التطبيق أولًا إن أردت اختبار `server_local` و`server_alias`؛ توقف الخادم لا يعني أن ملف hosts خاطئ.

ثم انتقل إلى **الإعدادات ← فحص وإعداد رابط overlay.test**. عند ظهور نافذة UAC وافق عليها إذا كنت تريد إضافة/تصحيح السطر.

**تنبيه:** لا تستخدم `python hosts_setup.py --apply` يدويًا دون فهم ما سيعدله؛ الأفضل استخدام معالج البرنامج للحصول على التأكيد والنسخة الاحتياطية والتشخيص.

## الحدود

التحقق الآلي تم في بيئة غير Windows؛ يجب اختبار نافذة UAC وملف hosts الحقيقي ومصدر TikTok LIVE Studio على جهاز Windows.
